# SQL 快取 graph 與原始 SQL 定義的比對問題清單

產生日期：2026-10-06。範圍：`data/sql_cache` 8 份快取、2401 個 module（procedures + views + functions）。

方法：把每個 module 的 definition 用獨立 regex 解析，與已存的 `sql_execution_graph` 比對。重現腳本：`.scratch/sql-graph-consistency/oracle_check.py`。

regex 比對很粗，每一項都是「待確認」的線索，不是定論。已人工確認的項目標示 ✅。

## 已確認一致（不需處理）

- 8 份快取：重建圖與已存圖相同（graph_version 11；nodes、relationships、parse_errors）。
- 每個 relationship 的 `source_location` 都在 definition 範圍內，`module_definition_length` 相符。
- 每個 module 都有對應 node；SP node 數 = procedures 數。
- SP 呼叫（EXEC → 已知 SP）：沒有漏邊。
- `SysErrorRecord`：使用者重建後已是 v11，一致。

## 問題 1 ✅：非 DML 陳述式內的子查詢，表格沒進圖（疑似建圖器缺陷）

共 209 筆（module × 表格）。原文有 `FROM/JOIN 表格`，圖裡該 module 沒有任何指向該表格的 reads/writes/uses 邊。
已人工確認的例子：
- `eFinance COMMON.CheckProgramAuth`：`if exists(select top 1 * from COMMON.UserProgram ...)`，圖有 10 個 dml_operation，沒有 UserProgram。
- `eFinance Mitoosi.CheckDepEntry`：`if Exists(select * from Mitoosi.MitoosiDep ...)`，圖只有 1 個 dml_operation（第 15 行），沒有 MitoosiDep。
- `PUR dbo.sp_BillConfirm`：`if (select ... from users ...) <> ''`，圖只有 `table:dbo.Bill`。
- `PUR dbo.sp_SO_UpdateInvFlag`：`set @POCount=(select count(InvFlag) from POrder ...)`，圖只有 `table:dbo.SOrder`。

假設（待你用 /grilling 查證）：建圖器只為 SELECT/INSERT/UPDATE/DELETE 等 DML 陳述式建 dml_operation，`IF` 述詞與 `SET`/`DECLARE` 內的子查詢不走訪。
