# 09 — Graph-Backed Path Evidence and Operator Projections

**What to build:** 將 proven `Database Invocation` 接入既有 `SQL Execution Graph`，形成可追溯的 `Execution Path` 與完整 `Path Evidence`；同時讓 refresh、analyze、reverse lookup、audit 與 CLI 對同一 source snapshot 輸出一致的 unified classification，並保留 contract revision 與 `Analysis Manifest` provenance。

**Blocked by:** 05 — Adapter and Fill Sink Parity; 06 — External Wrapper Contract Classification; 07 — Refresh-Time Contract Preflight; 08 — Atomic Refresh Commit and Scope Guards; existing `graph-gateway-contract` 03 — Evidence-Preserving Gateway Responses; existing `csharp-sql-execution-paths` 04 — First Execution Path Summary; existing `csharp-sql-execution-paths` 10 — Exact Path Evidence.

**Status:** resolved

- [x] proven stored-procedure invocation 能 join 到正確 SQL module 與 terminal DML，形成穩定的 `Execution Path`。（`service/execution_path_builder.py` `build_execution_paths`；見 `tests/test_execution_path_builder.py`、`tests/test_execution_path_integration.py`）
- [x] `Path Evidence` 保留 C# method、method semantics、invocation mode、command-text candidate、procedure target、terminal sink、connection source、branch predicate、source span、provenance 與 `Evidence Status`。（`_path_for_operation`/`_unresolved_path` merge `invocation_wrapper_evidence_fields`；見 `tests/test_exact_path_evidence.py`）
- [x] inline SQL 會保留為 inline `Database Invocation`；embedded `EXEC` 是額外 target evidence，不會被序列化成 stored-procedure mode。（`build_execution_paths` 只 join `stored_procedure` mode，inline invocations 仍留在 Gateway 的 invocation 清單與 `embedded_target` 證據；見 `tests/test_execution_path_builder.py::test_inline_sql_invocation_is_not_promoted_to_a_stored_procedure_path`）
- [x] unresolved target、ambiguous connection 或 dynamic SQL 會保留 documented unresolved evidence，不會被硬接成 proven graph relationship。（`_unresolved_path` reasons 如 `stored_procedure_not_in_graph`、`ambiguous_stored_procedure_graph_target`、`unresolved_dynamic_sql`）
- [x] refresh、analyze、SP/table reverse lookup、optional wrapper audit 與 CLI summary 對相同 invocation 回傳一致的 mode、sink、target、connection source、status 與 unresolved reason，且不會把 contract onboarding status 當成 `Evidence Status`。修正：`SPMatchProgram`／`TableMatchProgram`（`service/schemas.py`）原本遺漏 `invocation_mode`、`terminal_sink`、`connection_source`、`method_semantics`、`command_text_kind`、`command_text_literal`、`contract_fingerprint`、`contract_signature_version`、`contract_lifecycle_status`、`implementation_snapshot_reference`、`comparison_report_reference` 欄位，導致 reverse lookup 回應把這些欄位靜默丟棄；已補上欄位並以 `tests/test_graph_reverse_lookup.py::test_wrapper_projection_matches_analyze_and_reverse_lookup_surfaces` 的擴充 parity 斷言鎖定 analyze／execution path／find_by_sp／find_by_table／flow_chain 對同一 invocation 回傳一致值。`contract_status`（onboarding lifecycle）與 `evidence_status`（Evidence Status）維持獨立欄位。
- [x] operator projections 與 `Analysis Manifest` 保留本次使用的 contract fingerprint、signature revision、implementation snapshot、comparison report、binding revision 與 lifecycle status，能辨識 current、stale、conflicting contract evidence。（`service/analyze_service.py` `_contract_revision_reference` 產生 `analysis_manifest.contract_revision_reference`，於 `refresh_source` 回應中回傳）
- [x] SQL Execution Graph 仍是 SQL relationship、lineage、reverse lookup 與 terminal DML evidence 的唯一正式來源；optional discovery/audit 不得建立第二套 classifier。（`tools/discover_external_wrappers.py` 重用 `CSharpAnalysisGateway`／`reconcile_wrapper_observation`，未定義獨立分類規則）

## Comments

Verified the graph-backed Execution Path / Path Evidence infrastructure already existed from prior issues (05–08 plus `graph-gateway-contract` 03 and `csharp-sql-execution-paths` 04/10). The one real gap found was cross-surface field parity: `SPMatchProgram` and `TableMatchProgram` response schemas silently dropped several invocation-evidence fields that `analyze` and the `Execution Path` payload already exposed via `invocation_wrapper_evidence_fields`/`WRAPPER_EVIDENCE_FIELDS`. Added the missing fields to both schemas and extended the existing cross-surface parity test to cover them. Full test suite run (excluding two tests that require a live SQL Server driver / a hardcoded Windows path, both pre-existing and unrelated): 317 passed, 2 pre-existing unrelated failures.
