## Agent Brief

**Category:** bug
**Summary:** `CSharpParser.METHOD_PATTERN` must run in linear time on a
long run of whitespace.

**Current behavior:**
`METHOD_PATTERN` starts with `^[ \t]*(?P<access>...)?\s*`. When the
`access` group is absent, `[ \t]*` and `\s*` can split one run of
whitespace in O(n²) ways. `strip_csharp_comments` changes each comment to
spaces, so a large block of commented code becomes one long run.
`TOPCSCY/TOPCSCY/Services/DSM/ToolExcelCreateService.cs` takes about 16 s
in `_extract_methods`. Two callers use the pattern: `_extract_methods`
and the method lookup after an HTTP attribute (the `re.search` on the 500
characters after the attribute).

**Desired behavior:**
Each match of `METHOD_PATTERN` starts on the line of the declaration. One
place in the pattern takes the whitespace after the access modifier. A
possible form: `^[ \t]*(?:(?P<access>public|private|protected|internal)\s+)?`,
then the rest of the pattern without change. The named groups (`access`,
`static`, `virtual`, `override`, `abstract`, `async`, `ret`, `name`) keep
their meaning. Both callers get the fix, because they use the same
constant.

**Key interfaces:**
- `CSharpParser.METHOD_PATTERN` — the regex to change. Update its comment
  with the reason, as the `CLASS_PATTERN` comment does.
- `MethodInfo.location` line number — changes only for a method with no
  access modifier after one or more blank lines. It moves to the line of
  the declaration.
- `match.start()` in `_extract_methods` also feeds `_extract_method_body`
  and `_routed_action_name`. Check that the method body and the action
  name do not change.
- `_CACHE_VERSION` in `service/scan_store.py` — rises by one, with a v51
  comment. Merge the main line version number first, because parallel
  tickets can take the same number.

**Acceptance criteria:**
- [ ] A test runs `METHOD_PATTERN` (with `re.MULTILINE`) on 20,000 spaces
  and finishes in less than one second.
- [ ] A test shows that `void Foo()` and `static int Bar()` after blank
  lines get the line number of the declaration.
- [ ] A test shows that declarations with an access modifier, modifiers,
  a generic return type, a tuple return type and a generic method name give
  the same groups as before.
- [ ] `ToolExcelCreateService.cs` in TOPCSCY parses in less than one
  second (`parse_file`, idle machine).
- [ ] With the old-to-new comparison script of ticket 16, the full
  `parse_file` result on each `.cs` file of the 16 scan roots is the same,
  except for `analysis_time` and the method line number above. Report each
  other difference. Do not accept it without a report.
- [ ] The scan cache version rises by one.
- [ ] The full test suite has no new failures. (Known failures on HEAD:
  `test_program_refresh`, `test_wrapper_decompilation`, and the collection
  errors of `test_search_roles.py` and `test_sp_tables.py`.)

**Out of scope:**
- Other parts of `METHOD_PATTERN` (for example, the generic part of `ret`).
- Changes to `strip_csharp_comments`.
- Other slow causes in TTPUR (many files).
- The rescan of the shared cache. The user runs it locally.

### Implementation (2026-10-08)

> *This was generated by AI during implementation.*

- `METHOD_PATTERN` now starts
  `^[ \t]*(?:(?P<access>public|private|protected|internal)\s+)?`, the form
  in the brief. The rest of the pattern does not change. `_CACHE_VERSION`
  rises from 50 to 51 (the main line had 50). The tests are in
  `tests/test_csharp_parser_method_pattern.py`.
- `re.finditer(METHOD_PATTERN, " " * 20_000, re.M)` now takes less than
  0.01 s.
- `parse_file` on `TOPCSCY/TOPCSCY/Services/DSM/ToolExcelCreateService.cs`:
  0.37 s (3 runs, with the comparison below on 8 other processes).
- Old-to-new comparison: the script parsed each `.cs` file of the 16 scan
  roots (2,641 files) with the old pattern and the new pattern. It compared
  the full `parse_file` result. Only two fields change:
  - `analysis_time` (in each file).
  - `classes[].methods[].location.line_number`: 3,076 methods in 1,077
    files. Each one is a match with no `access` group. For each one, the
    lines from the old line to the new line are empty after
    `strip_csharp_comments`, and the new line is the declaration.
  - There are two types of these methods:
    - 2,059 methods with no access modifier (`void Foo()`, `static int Bar()`).
      This is the change in the triage comment.
    - 1,017 constructors (`public Foo(...)`). The brief does not name this
      type. The pattern has no constructor form, so a constructor matches
      with no `access` group: `ret` is `public` and `name` is the class
      name. This was also true before the fix. The old match also started at
      the first blank line (or comment line) before the constructor. Now it
      starts on the line of the constructor. The groups do not change.
  - Most of the changes are in TTPUR (1,758), TOPCSCY (558) and TTRDQ (184).
  - The method body, `line_count`, `action_name`, the SQL queries and the
    calls do not change. There is no error and no other difference.
- Users of the method line number: `ProjectScanner._find_class_and_method`
  finds the last method that starts on or before a SQL line. The lines
  between the old and the new start are empty, so no SQL line moves to a
  different method. `snippet_extractor` starts a snippet at the method line
  and takes `line_count` lines. The snippet now starts at the declaration,
  so it does not stop before the end of the method.
- Parse time of the 2,641 files (8 processes in parallel): old 420 s, new
  363 s. Now the slowest files do not depend on `METHOD_PATTERN`
  (`TTRDQ/Dev/DevPartDetail.aspx.cs` 9.8 s,
  `TOPCSCY/Models/HomeViewModel.cs` 7.9 s). These are out of scope.
- The shared scan cache needs a local rescan for v51 (out of scope; the
  user runs it).
