# 14 — The backward chain reports a call with no Bound Call Target

**What to build:** Ticket 06 puts a call with no Bound Call Target in the
forward chain `diagnostics` (`"kind": "unresolved_call"`). The backward walk
(ticket 07) goes from a method that reaches the table back to its callers.
When a caller calls through an interface with no single implementer, the
reversed edge does not exist. The backward walk then stops before the
action, and nothing tells the agent why.

Decide if the backward `/flow_chain` answer reports these stops, and in
which shape.

## Agent Brief

**Category:** enhancement
**Summary:** The backward `/flow_chain` answer reports a call that may reach a
reached method but has no Bound Call Target, in the forward `unresolved_call`
shape.

**Decisions (2026-10-07):**

- Only a call with `ambiguous_implementation` or `ambiguous_overload` can be a
  possible caller. Its `candidate_classes` hold the class of a reached method.
- A `no_local_implementer` call is never a possible caller. The class of the
  reached method would be a Local Implementer, so the call would have a target.
  The backward walk does not report it.
- The entry uses the forward `unresolved_call` shape (ticket 06), plus one
  field that names the reached method (the node) that the call may reach.
- The entries go in the backward chain `diagnostics`, beside the unproven
  Database Invocations with `requested_table`.

**Behaviour:**

- For each reached method of the backward walk, find each call with no Bound
  Call Target whose `candidate_classes` hold the class of that method.
- Give one entry for each such call and each reached method.
- Do not add an edge for the call. The walk does not follow it.
- Do not change the existing `ui_anchors` or the existing diagnostics entries.

**Acceptance criteria:**

- [x] An ambiguous interface call whose candidates hold the class of a reached
      method appears in the backward `diagnostics`
- [x] The entry has `kind`, `caller`, `call`, `reason`, `unresolved_reason`,
      `candidate_classes`, `source_span`, and the reached method field
- [x] A `no_local_implementer` call gives no entry
- [x] A call whose candidates do not hold a reached class gives no entry
- [x] The backward walk does not follow the call
- [x] RTTalentDB: record the entries for `IResumeStrategy` (three candidates)
      and the unchanged `backward_flow.py` numbers

**Out of scope:**

- Rendering in spec-rag. `_render_backward_chains` prints no `diagnostics` and
  no `program_screen` entry. Open a spec-rag ticket for both.
- A glossary term for "a call with no Bound Call Target" (`/domain-modeling`).
- Matching a candidate class by simple name only: check that the scan gives
  qualified names. If not, note the risk in the ticket.

**Pointers:** `service/flow_chain_builder.py` (`_bound_call_graph`,
`_unresolved_call_diagnostic`, `build_backward_chains`); ADR-0044; tickets 06, 07.
