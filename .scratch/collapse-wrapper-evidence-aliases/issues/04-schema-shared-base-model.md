# 04 — Collapse the three response schemas onto one shared canonical base model

**What to build:** `PathEvidenceResponse`, `SPMatchProgram`, and `TableMatchProgram` in `service/schemas.py` stop independently redeclaring the ~90-field wrapper-evidence bag and instead inherit a single shared base model declaring the canonical field set once. The JSON response shape stays flat (no nested `wrapper_evidence` object) — this is a field-count reduction, not a shape change.

**Blocked by:** 01 (dropping the `evidence` field specifically requires spec-rag to have already migrated off it; the other 16 canonicalized field names are safe to drop from the schema regardless of domain-side timing, since Pydantic ignores extra dict keys it doesn't declare).

**Status:** resolved

- [x] `service/schemas.py` gains one shared base model (e.g. `WrapperEvidenceFields(BaseModel)`) declaring exactly the 17 canonical wrapper-evidence fields from the spec's table (`status`, `selection_source`, `contract`, `contract_mode`, `contract_sink`, `candidate_contracts`, `scan_root`, `source_available`, `review_candidate`, `classification_reason`, `mode_reason`, `wrapper_method`, `stored_procedure_mode`, `evidence_status`, `contract_signature_version`, `contract_lifecycle_status`, `source_snapshot_hash`) plus every already-single-named field currently shared across all three classes.
- [x] `PathEvidenceResponse`, `SPMatchProgram`, and `TableMatchProgram` inherit from the shared base model instead of independently redeclaring these fields.
- [x] None of the 20 dropped aliases from ticket 02, nor the `evidence` field from ticket 03, remain declared on any of the three response schemas.
- [x] The ten dual-fact pairs (`implementation_identity`/`wrapper_implementation_identity` and friends, `receiver_type`/`wrapper_receiver_type`, `external_wrapper_method`/`wrapper_method`) and every already-single-named field remain declared exactly as today — this ticket does not touch response shape for anything outside the 17-group canonical collapse.
- [x] `tests/test_path_evidence_api.py` gains an assertion that a `/path_evidence` response contains `evidence_status` and not `evidence` inside the wrapper-evidence fields, and that it contains no other dropped alias key.
- [x] An equivalent assertion is added for `/refresh`'s `wrapper_summary` entries (`SPMatchProgram`/`TableMatchProgram`-shaped) — exactly one name per collapsed concept, no dropped alias key present.
- [x] Full existing test suite passes, including any existing test that constructs a `PathEvidenceResponse`/`SPMatchProgram`/`TableMatchProgram` by keyword argument using a now-dropped field name — those call sites are updated to the canonical name.

**Further Notes:** Field counts dropped from 67/68/74 to 51/48/54 on `PathEvidenceResponse`/`SPMatchProgram`/`TableMatchProgram` respectively. `contract_signature_version`/`contract_lifecycle_status` were only previously declared on `SPMatchProgram`/`TableMatchProgram` (not `PathEvidenceResponse`); per the spec's explicit 17-field canonical list they now live on the shared base and are gained by `PathEvidenceResponse` too — this surfaces domain values (`project_wrapper_evidence` already emits them) that were previously silently dropped by Pydantic's `extra="ignore"`, not a behavior regression. Fields shared by only two of the three classes (e.g. `invocation_mode`, `terminal_sink`, `connection_source`, `contract_fingerprint`) stay declared individually on those two classes per the ticket's explicit scope boundary ("this ticket does not touch response shape for anything outside the 17-group canonical collapse"). No production call sites constructed these schemas with a dropped alias keyword (all three construction sites in `service/analyze_service.py` use `**dict` spreads from `WRAPPER_EVIDENCE_FIELDS`-filtered mappings, already canonical since tickets 02/03). New tests: `tests/test_schemas.py` (schema-level regression: inheritance, 17 canonical fields, 20 dropped aliases absent, dual-fact pairs independent) and two additions to `tests/test_path_evidence_api.py` (`/path_evidence` and `/refresh` HTTP-boundary assertions). Full suite: 396 passed, same 11 pre-existing failures as tickets 02/03 baseline (verified unrelated to this change), `test_search_roles.py`/`test_sp_tables.py` still fail collection for the pre-existing no-ODBC-driver reason.
