# 📦 資料搬遷手冊 — 從公司電腦搬到另一台電腦

## ❓ 為什麼要手動搬

`.gitignore` 排除下列資料，所以 `git pull` 拿不到它們。你必須手動複製這些資料。

所有路徑都從「工作目錄」算起。工作目錄是放兩個專案的那一層。

## 📋 要搬的資料

### 1. ESP 規格書（`llamaindex-spec-rag/`）

| 路徑 | 內容 | 必要性 |
|------|------|--------|
| `data/systems/` | 每個系統的 Markdown 規格書 | 必搬 |
| `docs_json_data/processed_versions.json` | 每個規格書檔案的 Processed Version 紀錄 | 必搬 |
| `docs_json_data/json_data.json` | 舊爬蟲紀錄 | 必搬 |
| `storage/` | 每個系統的索引 | 必搬 |
| `chroma_db/` | 向量資料庫 | 必搬，與 `storage/` 一起搬 |
| `catalog/system_catalog.json` | 系統清單與 `spec_url` | 只在公司電腦改過時搬 |
| `data/archive_raw/` | 原始 `.doc`／`.docx` 檔（約 350 MB） | 選搬，只當備份 |

> ⚠️ **一定要搬 `processed_versions.json`。** 少了這個檔案，系統會把每個規格書檔案都當成落後 ESP，下次更新會全部重新下載。

> ⚠️ **`storage/` 與 `chroma_db/` 要一起搬。** 只搬其中一個，索引會不一致。不搬這兩個就要重建索引，重建會產生 embedding 費用。

### 2. SQL Server 快取

| 路徑 | 內容 | 必要性 |
|------|------|--------|
| `Impact_analysis_system/data/sql_cache/` | SQL Server schema 快取（`伺服器__資料庫.json`、`.index.json`、`.meta.json`） | 必搬 |
| `llamaindex-spec-rag/catalog/SQLServerData.json` | 要掃描的伺服器與資料庫清單 | 只在公司電腦改過時搬 |

新電腦連不到公司 SQL Server 時，系統只能讀 `sql_cache/`。所以這個資料夾一定要搬。

### 3. C# 分析資料（`Impact_analysis_system/data/`）

| 路徑 | 內容 |
|------|------|
| `repos/` | 從 Azure Repos 取得的原始碼 |
| `scan_cache/` | C# 掃描結果 |
| `code_embeddings/` | 程式碼 embedding |
| `derived_execution_evidence/` | 執行路徑證據 |
| `decompilation_cache/` | 反編譯快取 |

建議一起搬。不搬的話，新電腦要連 Azure Repos 才能重建。

> 💡 兩台電腦的 Impact 程式版本不同時，`derived_execution_evidence/` 的舊版存檔算未命中。提問時，系統從 `scan_cache/` 與 `sql_cache/` 重新推導。這不需要連線。

### 4. 環境設定

| 路徑 | 內容 |
|------|------|
| `llamaindex-spec-rag/.env` | API key、路徑、掃描帳密 |
| `Impact_analysis_system/.env` | DB 連線、Azure OpenAI、Azure DevOps PAT |

> 🔒 `.env` 有密碼與 API key。用加密的方式傳送。不要用 email 傳送。

## 🚫 不要搬的資料

下列資料夾與作業系統有關。在新電腦上重新建立它們。

- `.venv/`
- `__pycache__/`、`.pytest_cache/`、`.mypy_cache/`
- `impact_web/frontend/node_modules/`、`impact_web/frontend/dist/`
- `Impact_analysis_system/.vs/`
- `Impact_analysis_system/tools/StaticAnalyzerHost/bin/`、`obj/`

## 🔧 搬遷步驟

### Step 1｜在公司電腦停止服務

1. 關閉 Web 介面。
2. 停止 Impact 服務。

> ⚠️ 服務執行時，`chroma.sqlite3` 可能正在寫入。這時複製會得到損壞的檔案。

### Step 2｜打包資料

1. 把[要搬的資料](#-要搬的資料)壓縮成一個 zip 檔。
2. 保留原本的資料夾結構。

### Step 3｜在新電腦還原資料

1. 確認新電腦已有兩個專案的程式碼。
2. 把 zip 檔解壓縮到工作目錄。
3. 確認每個資料夾都在原本的路徑。

### Step 4｜修改 `.env`

1. 打開兩個專案的 `.env`。
2. 找出 Windows 格式的路徑（例如 `C:\...`）。
3. 把每個路徑改成新電腦的路徑。

需要檢查的變數：`SYSTEMS_ROOT_DIR`、`CATALOG_PATH`、`STORAGE_ROOT_DIR`、`CHROMA_DB_PATH`、`CRAWLER_JSON_DIR`、`IMPACT_REPO_DIR`、`OUTPUT_DIR`、`LOG_FILE`。

### Step 5｜確認結果

1. 依 [使用說明書.md § 快速開始](./使用說明書.md#-快速開始) 建立 `.venv`。
2. 啟動 Web 介面。
3. 問一個已知系統的問題。
4. 確認答案有引用規格書與 SQL 物件。

## ⛔ 搬完之後的限制

新電腦沒有公司網路時，下列更新不能用：

| 更新 | 需要的 Update Capability |
|------|--------------------------|
| 規格書更新 | ESP 存取與 Microsoft Word（只能在 Windows 執行） |
| SQL cache 更新 | SQL Server 存取 |
| C# 掃描結果更新 | Azure Repos 存取 |

問答功能仍然可以用，因為它只讀搬過來的資料。要更新資料時，回到公司電腦更新。然後再照本手冊搬一次。
